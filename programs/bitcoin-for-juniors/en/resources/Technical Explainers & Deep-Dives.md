## **Chapter 3: Fractional Reserve Banking — How It Works**

### **Simple Analogy: The Bike Lending**

Imagine you lend your bike to a banker. Instead of storing it:

* Banker lends it to Alice (Monday-Wednesday)
* Then lends it to Bob (Thursday-Saturday)
* Promises both they can use it whenever they want

**The Problem:** Only one bike exists. If Alice and Bob both show up Tuesday, problem.

**This is fractional reserve banking:**

* Bank receives $100 from you
* Keeps $10 (reserve requirement)
* Lends out $90 to borrower
* Borrower deposits $90 in another bank
* That bank keeps $9, lends out $81
* Cycle continues...

**Result:** $100 initial deposit becomes \~$1,000 in total claims across the system.

**Risk:** If everyone withdraws simultaneously, banks can't pay. This is a bank run.

## **Chapter 5: Satoshi's Insight — The Double Spending Problem**

### **Why Digital Money Was Hard Before Bitcoin**

**Problem:** In physical world, you can't spend the same coin twice. Once it leaves your hand, it's gone.

**In digital world:** A file is just data. You can copy it. How do you prevent someone from spending the same Bitcoin twice?

**Previous attempts failed because:**

* Needed a trusted server to track who spent what (centralized)
* Server could be hacked, shut down, or act dishonestly
* No way to verify without trusting someone

### **Satoshi's Solution: Nakamoto Consensus**

Instead of one trusted server, use a decentralized network where:


1. **Everyone keeps a copy** of the transaction history (ledger)
2. **Miners compete** to add valid transactions to the ledger
3. **Math proves** which chain is legitimate (the one with most computational work)
4. **Network agrees** on the valid history; cheaters are ignored

**Result:** No central authority needed. Math and consensus prevent double spending.

## **Chapter 8: Hash Functions — The Digital Fingerprint**

### **What is a Hash?**

A hash function takes ANY input and produces a fixed-length output (fingerprint).

**Example (SHA-256):**

```
Input: "Bitcoin"
Output: 9b74f89fb3ce78fc3ca86f41e4b0e4ee1a8c7edb5b4b8a9d2e5f8c1a2b3d4e5f
(always 64 characters)

Input: "Bitcoin is great"
Output: 7a3f8d9e2b4c1a6f5e8d3c2b9f7a4e1d6c8b3a9f5d2e7c1a4b8f6e3a9d2c5b1f
(still 64 characters)

Change one letter: "bitcoin" (lowercase)
Output: 88c2f9e3b6a1d4c2f9e8b5a2c3d6e7f1a4b8c2d5e8f1a4b7c0d3e6f9a2b5c8e
(completely different)
```

### **Why This Matters for Bitcoin**


1. **Immutability:** If anyone changes a transaction, the hash changes. New block doesn't match the chain → rejected.
2. **Verification:** You can hash a block yourself and compare. If your hash matches the chain's hash, the block is authentic.
3. **Security:** To fake a transaction, you'd need to recalculate hashes of that block AND all blocks after it, all faster than the network adds new blocks. Exponentially hard.

## **Chapter 8: Public & Private Keys — The Math Behind Bitcoin Ownership**

### **How It Works (Simplified)**

**Two paired keys generated by cryptography:**


1. **Private Key:** Secret number only you know (like your password, but more powerful)
   * Proves you own Bitcoin
   * Authorizes spending
   * If someone has it, they can steal all your Bitcoin
   * 256-bit number (impossible to guess)
2. **Public Key:** Derived from private key mathematically; can be shared freely
   * Everyone can see it
   * Proves private key holder authorized a transaction
   * Impossible to reverse-engineer private key from public key

### **The Transaction**


1. You create a transaction: "Send 1 BTC to address XYZ"
2. You sign it with your **private key** (creates digital signature)
3. Network verifies signature using your **public key**
4. Signature proves you authorized it without revealing private key

**Why It Works:** Math guarantees only private key holder could create that signature.

## **Chapter 8: UTXO Model — How Bitcoin Accounting Works**

### **Contrast to Bank Account Model**

**Your Bank Account:**

```
Balance: $500
Send $100 → Balance: $400
(Bank updates balance in database)
```

**Bitcoin UTXO Model:**

```
You own: UTXO of 0.5 BTC (unspent transaction output)
You spend it → Creates two outputs:
  - 0.1 BTC to recipient
  - 0.4 BTC to your change address
(Old UTXO destroyed; two new UTXOs created)
```

### **Why UTXO Matters**


1. **Accounting:** No central ledger updating balances. Each transaction is final; creates new UTXOs.
2. **Security:** Each transaction input must reference a valid previous output. Can't double-spend what's already been spent.
3. **Verification:** Anyone can trace backward: does this output actually exist in the blockchain? Yes → valid.

### **Real Example**

```
Alice has UTXO: 0.5 BTC (received from Bob)
Alice buys coffee: 0.01 BTC

Transaction:
Input: Alice's UTXO (0.5 BTC) [destroyed]
Output 1: 0.01 BTC to coffee shop [new UTXO]
Output 2: 0.49 BTC to Alice's change address [new UTXO]

Alice now owns: 0.49 BTC UTXO
Coffee shop now owns: 0.01 BTC UTXO
```

## **Chapter 9: Proof of Work — Why Bitcoin is Secure**

### **The Core Idea**

To add a block, miners must solve a hard math puzzle (find a hash meeting a difficulty target).

**Why hard?**

* Requires enormous computational work
* Takes energy = costs money
* Only rewarded if solution is correct

**Why it secures Bitcoin:**


1. **Attacking costs money:** To rewrite past transactions, attacker must redo ALL the computational work from that point forward, while the network keeps adding new blocks (moving target).
2. **Economics prevent attack:** Block reward (6.25 BTC) is worth $250,000+. To rewrite history, attacker must spend that in electricity. Not rational.
3. **Honest chain grows faster:** Attacker with 40% hash power is slower than honest network (60% power). Honest chain always wins.

### **51% Attack Threshold**

If someone controlled 51%+ of network hash rate:

* Could reorder transactions, reverse recent payments
* But still couldn't: steal Bitcoin from your address (no private key), change past confirmations (would require recalculating all future blocks), break cryptography

**Cost to attack:** \~$50 billion in hardware + $10+ billion in electricity (estimates vary). ROI negative. Not rational.
